# 2026-09-30

## ChatGPT / 豆包账号导入功能修复（all2api）

诊断结论：
- ChatGPT 导入主链路此前已实现且可用（统一入口 `POST /admin/api/channels/{slug}/accounts/provision/import`，flow=`token-import`），但存在两个正确性缺陷：重复导入同一 token 会重置账号 status/enabled 且重复计数 added；错误条目无定位信息。
- 豆包导入完全未实现：`DoubaoProvisioner.import_accounts` 直接抛 `import_not_supported`，manifest 无导入 flow。

改动（services/api）：
- `app/adapters/chatgpt/provisioner.py`：`token_import` 增加凭据存在性检测（`_credentials_exist`），重复导入改为 refreshed 计数并仅轮换凭据、不再重置账号状态；错误信息带条目序号；`_result` 支持 refreshed。
- `app/adapters/doubao/manifest.py`：新增 `cookie-import` flow（kind=token_import，supports.import=True，cookie/accounts/name/priority/enabled 字段）。
- `app/adapters/doubao/provisioner.py`：实现 `import_accounts`——解析 Cookie 头字符串、cookies 字典/浏览器数组、doubao2api 会话文件（cookies+params）；强制要求 sessionid/sessionid_ss；凭据形状与 QR 登录产出一致（Cookie/cookies/msToken/User-Agent/Origin/Referer+设备参数）；account_id 缺省为 `cookie-<sessionid指纹12位>`；支持绑定已有 profile、重复导入 refreshed、幂等键。
- `app/adapters/doubao/credentials.py`：MemoryCredentialStore 增加 `read`，atomic_write 改为同账号覆盖写（对齐 DatabaseCredentialStore 语义）。
- 新增 `tests/test_doubao_cookie_import.py`（10 用例）；更新 test_doubao_native.py、test_native_provision_e2e.py 的 flow 白名单。

验证：154 个后端测试全过；ruff 与 check_no_legacy 通过；8090 端口实测——豆包导入/批量/异常 422/幂等/重复刷新、账号列表生效、渠道自动启用、调试台可选中账号并携凭据到达上游；ChatGPT 用真实 sub2api 导出文件（10 账号）重复导入全部 refreshed。8080 运行实例为旧代码，需重启生效。

参考项目要点：doubao2api 要求 cookies 内含 sessionid（src/core/client.py:2353）；chatgpt2api 账号即 access_token+email+type（data/accounts.json）。

## 项目启动（本地开发方式）

- 后端：`services/api/.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload`
- 前端：`web/node_modules/.bin/vite --host 127.0.0.1 --port 5173`（Vite 代理 /admin/api 与 /v1 到 8080）
- 入口：http://127.0.0.1:5173（管理员 admin/admin123）
- 注意：直接调 8080 API 时 Origin 头必须写 `http://127.0.0.1:8080`（与请求 host 一致），否则登录返回 forbidden。
