# All2API 能力发展路线图

> 文档类型：产品规划  
> 创建时间：2026-09-28  
> 维护者：开发团队  
> 状态：活跃

## 概述

本文档规划 All2API 各渠道能力的开发计划，明确已支持、开发中和计划中的功能。

## 当前支持范围（v0.2.0）

### ✅ 全面支持

#### Chat（聊天补全）
- **渠道**：WorkBuddy, ChatGPT, Doubao
- **协议**：OpenAI, Anthropic, Responses
- **特性**：
  - ✅ 流式/非流式响应
  - ✅ 工具调用
  - ✅ 多轮对话
  - ✅ 系统消息
  - ✅ 令牌计数（部分渠道）
  - ✅ 账户选择和负载均衡
  - ✅ 失败重试和降级
- **接口**：
  - `POST /v1/chat/completions` (OpenAI 格式)
  - `POST /v1/messages` (Anthropic 格式)
  - `POST /v1/responses` (Responses 格式)

## 开发路线图

### Phase 1: 核心多媒体能力（P1 优先级）

#### P1-1: ChatGPT 图像生成
**预计工期**：5-7 天  
**依赖**：无

**范围**：
- 支持 DALL-E 3 和 DALL-E 2 模型
- 实现 `/v1/images/generations` 接口
- 请求参数：
  - `prompt`: 图像描述
  - `model`: dall-e-3 / dall-e-2
  - `n`: 生成数量（1-10）
  - `size`: 图像尺寸（1024x1024, 1792x1024, 1024x1792）
  - `quality`: standard / hd
  - `style`: vivid / natural
- 响应格式：OpenAI 标准格式

**技术任务**：
- [ ] 调研 ChatGPT 平台 DALL-E 接口规格
- [ ] 实现请求映射和参数验证
- [ ] 处理异步生成（如需要）
- [ ] 添加 E2E 测试
- [ ] 更新 manifest: `capabilities=("chat", "image")`
- [ ] 更新 API 文档

**验收标准**：
- [ ] 可通过 API 密钥调用 DALL-E 生成图像
- [ ] 返回图像 URL 或 base64 数据
- [ ] 错误处理（配额超限、内容策略违规）
- [ ] Contract tests 通过

## 不支持的能力

以下能力明确**不在开发计划内**：

### ❌ 图像编辑（短期）
- **原因**：上游能力不明确，需求优先级低
- **接口**：`POST /v1/images/edits`
- **返回**：404 capability_not_supported

### ❌ 可编辑文件任务查询
- **原因**：ChatGPT 平台特定功能，通用性不足
- **接口**：`GET /v1/editable-file-tasks`
- **返回**：404 capability_not_supported

### ❌ Token 计数（非 chat）
- **原因**：多媒体内容 token 计数复杂且非标准
- **接口**：`POST /v1/messages/count_tokens`（仅支持 chat）
- **返回**：404 capability_not_supported

## 决策记录

### DR-001: 为什么从 manifest 移除未实现能力？
**日期**：2026-09-28  
**决策**：将 ChatGPT 和 Doubao 的 manifest capabilities 缩减为仅 `("chat",)`

**理由**：
1. **诚信原则**：manifest 是对外承诺，必须准确反映实际能力
2. **用户体验**：避免用户调用后发现不支持，造成混淆
3. **测试覆盖**：只有 chat 有完整的 contract tests
4. **渐进式增强**：实现后再添加声明，而非预先声明

**影响**：
- `/v1/images/generations` 等接口在非支持渠道上返回 404
- `/v1/models` 不会列出未实现的多媒体模型
- 用户可通过文档明确了解支持范围

**替代方案被拒绝**：
- ❌ 保留声明但返回 501：违背 manifest 契约
- ❌ 部分实现（如仅支持默认参数）：用户体验差，维护成本高

---

### DR-002: 为什么不立即实现多媒体接口？
**日期**：2026-09-28  
**决策**：P0-4 只完成 manifest 修正，将实现推迟到 P1

**理由**：
1. **优先级**：Chat 是核心能力，多媒体是增值功能
2. **风险控制**：需要调研上游接口，避免盲目实现
3. **质量保证**：需要为每个能力编写完整测试
4. **资源有限**：P0-4 预算 10-14 天，实现所有能力不现实

**权衡**：
- 短期功能受限 vs 长期质量保证
- 选择：质量优先
