# 渠道适配器开发规范

本文定义新增平台的唯一扩展入口。新增平台是代码变更，不在管理页面动态执行任意代码。适配器必须能够在没有三个源项目目录、端口和包的环境中独立构建。

## 1. SPI 总览

一个渠道至少由以下对象组成（Go 类型以 `internal/ports/*.go` 为准）：

```text
ports.AdapterManifest       静态身份、协议和能力（internal/ports/registry.go）
ports.Adapter (+ 可选接口)   模型发现、请求调用、流式响应、多媒体能力（internal/ports/gateway.go）
<slug>.Provisioner          新增、轮询、完成、取消、刷新账号（各渠道包内 provision.go）
ports.ProvisionRepository   provision 会话、幂等记录和账号导入持久化（internal/ports/provision.go）
ports.SecretBox / CredentialRepository  加密写入、读取、轮换凭据（internal/ports/keys.go、provision.go）
映射函数                    平台账号 → ports.AccountImport，平台模型 → ports.ModelDescriptor
错误类型                    平台错误 → 实现 StatusCode()/Kind() 的错误（如 ports.TransportError）
```

实际的 Go 形状（摘自 `internal/ports`，不要把实现直接写进 `internal/transport/http`）：

```go
// internal/ports/registry.go
type AdapterManifest struct {
	Slug         string
	Name         string
	Version      string
	Protocols    []string
	Capabilities []string
}

type AdapterRegistration struct {
	Manifest AdapterManifest
	Adapter  Adapter
}

// internal/ports/gateway.go
type Adapter interface {
	Channel() string
	Models(context.Context) ([]ModelDescriptor, error)
	Chat(context.Context, ChatInput) (ChatResult, error)
}

// 需要账号的渠道按需实现以下可选接口，gateway 用类型断言识别能力。
type AccountAwareAdapter interface {
	Adapter
	ChatWithAccount(context.Context, ChatInput, string) (ChatResult, error)
}

type AccountModelAdapter interface {
	Adapter
	ModelsWithAccount(context.Context, string) ([]ModelDescriptor, error)
}

type AccountStreamAdapter interface {
	AccountAwareAdapter
	ChatStreamWithAccount(context.Context, ChatInput, string, func(StreamChunk) error) error
}

type AccountCapabilityAdapter interface {
	Adapter
	CapabilityWithAccount(context.Context, CapabilityInput, string) (CapabilityResult, error)
}
```

账号流程目前没有统一的 port 接口，各渠道 `Provisioner` 遵循同一方法集约定（参数以各包为准，例如 ChatGPT 的 `Complete` 额外接收 payload）：

```go
// internal/adapters/workbuddy/provision.go（doubao/chatgpt 同形）
type Provisioner struct {
	Repository ports.ProvisionRepository
	Box        ports.SecretBox
	// 平台 client、TTL、时钟等由构造函数注入
}

func (p *Provisioner) Start(ctx context.Context, flow string, payload map[string]any, idempotency string) (map[string]any, error)
func (p *Provisioner) Poll(ctx context.Context, sessionID string) (map[string]any, error)
func (p *Provisioner) Complete(ctx context.Context, sessionID, idempotency string) (map[string]any, error)
func (p *Provisioner) Cancel(ctx context.Context, sessionID string) error
// 支持凭据刷新的渠道（wb、chatgpt）另有：
func (p *Provisioner) Refresh(ctx context.Context, nativeID, actor, ip string) (map[string]any, error)
```

账号导入由 `internal/application/accounts/provision.go` 的 `ProvisionService.Import` 统一处理，表示管理员主动提交本次新增账号所需的 token 或账号材料，适用于需要直接导入凭据的渠道；它不能读取外部项目的账号列表，也不能恢复已删除的“同步账号”功能。账号目录只由本项目的 provision 流程写入。

adapter 只通过构造函数拿到依赖（配置值、凭据解析函数、HTTP/browser client、时钟、日志）；不得直接读取环境变量或全局 SQLite 连接。配置统一由 `internal/config` 加载，在 `cmd/all2api/main.go` 中注入。

## 2. Manifest 契约

每个 manifest 必须声明：

| 字段 | Go 字段 | 要求 |
|---|---|---|
| `slug` | `Slug` | 小写稳定标识，只允许 `[a-z0-9-]`；发布后不改名 |
| `display_name` | `Name` | 管理面展示名称，不用于路由判断 |
| `adapter_version` | `Version` | 语义版本；配置或凭据格式变化必须升版本 |
| `protocols` | `Protocols` | 实际支持的入站协议，如 `openai`、`anthropic`、`responses` |
| `capabilities` | `Capabilities` | `chat`、`image`、`video`、`audio`、`file` 等，未实现不得声明；gateway 和 playground 按此拒绝未声明能力 |
| `account_flows` | 未建模 | flow id、类型、字段 schema、是否异步、幂等和权限 |
| `config_schema` | 未建模 | 内置客户端所需配置；Secret 标记为 secret，不回显 |
| `health_checks` | 未建模 | 配置缺失、平台不可达、凭据失效、浏览器故障等状态映射 |
| `limits` | 未建模 | 并发、超时、最大 payload、是否支持重试 |

标为“未建模”的字段是目标契约，当前 `ports.AdapterManifest` 尚未包含，新增时必须先扩展 port 而不是在 transport 层补平台分支。

前端和管理 API 只读取 manifest。新增渠道后，渠道列表、账号筛选、Key 编辑、模型目录和新增账号入口都从 registry 动态生成。

## 3. 目录模板

```text
cmd/
├─ all2api/main.go                # 装配配置、存储、adapter、provisioner 和 HTTP server
├─ doubao-browser-worker/main.go  # Doubao 浏览器 worker
└─ media-worker/main.go           # 媒体 worker
internal/
├─ domain/scope/                  # Key channel/model scope 等纯领域规则
├─ application/
│  ├─ accounts/                   # service.go、provision.go
│  ├─ keys/service.go
│  ├─ gateway/service.go
│  └─ admin/ auth/ health/ media/ playground/
├─ ports/                         # gateway.go、registry.go、provision.go、keys.go、upstream_errors.go ...
├─ adapters/
│  ├─ registry/registry.go
│  ├─ workbuddy/                  # adapter.go、client.go、provision.go、errors.go、*_test.go
│  ├─ doubao/                     # adapter.go、client.go、browser_client.go、provision.go、qr.go
│  ├─ chatgpt/                    # adapter.go、client.go、oauth.go、provision.go、sentinel.go ...
│  ├─ grok/                       # adapter.go、catalog.go、client.go
│  └─ fake/adapter.go             # 测试用 fake adapter
├─ infrastructure/
│  ├─ crypto/                     # Fernet 凭据加密
│  ├─ persistence/                # SQLite 与 migrations/
│  ├─ security/  tokens/  media/
├─ browser/                       # 浏览器 worker 与 cdp/
├─ protocols/                     # anthropic/responses 协议转换
├─ scheduler/                     # 账号池与调度
└─ transport/http/                # 按领域拆分的 HTTP handler
```

新渠道以 `internal/adapters/<slug>/` 为单位组织，测试文件 `*_test.go` 与实现放在同一包内。

## 4. Registry 规则

registry 是唯一装配点（`internal/adapters/registry/registry.go`）：

```go
items := map[string]ports.AdapterRegistration{
	"wb": {
		Manifest: ports.AdapterManifest{Slug: "wb", Name: "WorkBuddy", Version: "0.1.0", Protocols: []string{"openai", "anthropic", "responses"}, Capabilities: []string{"chat"}},
	},
	"doubao":  {Manifest: ports.AdapterManifest{Slug: "doubao", Name: "Doubao" /* ... */}},
	"chatgpt": {Manifest: ports.AdapterManifest{Slug: "chatgpt", Name: "ChatGPT" /* ... */}},
	"grok":    {Manifest: ports.AdapterManifest{Slug: "grok", Name: "Grok" /* ... */}},
}
```

`registry.New(adapters)` 把 `cmd/all2api/main.go` 传入的 `map[string]ports.Adapter` 绑定到对应 manifest，并提供 `List()`/`Get(slug)`。

路由、账号用例、Key 用例和前端不得维护第二份渠道枚举。未知 slug 返回 `404 channel_not_found`；manifest 存在但配置不完整返回 `409 channel_not_configured`；平台短暂不可用映射为 `503/504`。

新增平台可以直接复制以下最小模板，再逐步补齐平台逻辑；模板位置固定在 `internal/adapters/<slug>/`，是代码扩展点而不是页面配置点：

```go
// internal/adapters/<slug>/adapter.go
package <slug>

type Adapter struct{ client *Client }

func NewAdapter(client *Client) *Adapter { return &Adapter{client: client} }

func (a *Adapter) Channel() string { return "<slug>" }
func (a *Adapter) Models(ctx context.Context) ([]ports.ModelDescriptor, error) { ... }
func (a *Adapter) Chat(ctx context.Context, input ports.ChatInput) (ports.ChatResult, error) { ... }
// 需要账号时实现 ModelsWithAccount / ChatWithAccount / ChatStreamWithAccount / CapabilityWithAccount

// internal/adapters/<slug>/provision.go
type Provisioner struct {
	Repository ports.ProvisionRepository
	Box        ports.SecretBox
}

func (p *Provisioner) Start(ctx context.Context, flow string, payload map[string]any, idempotency string) (map[string]any, error) { ... }
func (p *Provisioner) Poll(ctx context.Context, sessionID string) (map[string]any, error) { ... }
func (p *Provisioner) Complete(ctx context.Context, sessionID, idempotency string) (map[string]any, error) { ... }
func (p *Provisioner) Cancel(ctx context.Context, sessionID string) error { ... }

// internal/adapters/registry/registry.go —— 在 New 的 items 中追加 manifest
"<slug>": {Manifest: ports.AdapterManifest{Slug: "<slug>", Name: "<Display name>", Version: "0.1.0", Protocols: []string{"openai"}, Capabilities: []string{"chat"}}},

// cmd/all2api/main.go —— 把 adapter 加入装配表
adapters := map[string]ports.Adapter{
	// ...
	"<slug>": <slug>.NewAdapter(client),
}
```

模板中的 `...` 必须替换为真实 schema、错误映射和契约测试；不得把平台字段、Secret 或 HTTP 客户端直接写进 `internal/transport/http`。

当前已知技术债：provisioner 尚未抽象为 port，`internal/transport/http/server.go` 按具体类型持有三渠道 `Provisioner`，`internal/application/accounts/provision.go` 的导入入口含渠道白名单。新平台不得扩大这类分支；需要接入账号流程时，应先把 provisioner 方法集提升为 `internal/ports` 接口并由 registry 装配。

## 5. 新平台接入步骤

1. 建立 `internal/adapters/<slug>/`，在 registry 中提交 manifest，并在 `internal/config/config.go` 增加配置项。
2. 实现 `ports.Adapter` 及所需可选接口：模型、非流式、流式、多媒体、错误映射。
3. 实现 `Provisioner`：至少一个 flow；说明凭据存储、幂等键、超时、取消和审计事件。
4. 实现映射，把平台账号/模型/usage 转成 `ports.AccountImport`、`ports.ModelDescriptor`、`ports.Usage`；特有字段只放版本化 `ext`。
5. 在 registry 和 `cmd/all2api/main.go` 注册，不修改 gateway/transport/application 的平台分支。
6. 添加配置迁移、Secret 模板（`.env.example`）、契约 fixture 和合规/许可证记录。
7. 增加 adapter contract、错误矩阵、账号流程状态机和最小 E2E（`go test ./...` 可运行）。
8. 更新 manifest 文档、OpenAPI、运维告警和变更记录。

若必须修改通用核心，先证明是所有渠道共有的 port/领域规则，并在 ADR 中记录；不得为了一个平台添加 `if slug == ...`。

## 6. 账号 provision 规则

`Provisioner` 的 flow 必须声明：

```json
{
  "id": "oauth-qr",
  "kind": "qr|oauth|token_import|manual",
  "schema": {"type": "object", "properties": {}},
  "supports": {"start": true, "poll": true, "complete": true, "cancel": true},
  "timeout_seconds": 300,
  "idempotency": "required"
}
```

通用账号服务只负责：校验渠道和 flow、生成/校验 idempotency key、持久化会话状态（`ports.ProvisionRepository`）、调用 provisioner、写审计、归一化账号和刷新模型。它不认识 `realm`、`account_id`、`callback`、`access_token` 等平台字段。

## 7. 错误和重试

adapter 必须把平台错误归类为统一错误类型：返回的 error 实现 `StatusCode() int` 和 `Kind() string`（参见 `ports.TransportError`、`internal/adapters/workbuddy/errors.go`），gateway 据此生成响应，未分类错误统一映射为 `502 adapter_error`。目标 `Kind` 取值：`invalid_request`、`auth_required`、`credential_expired`、`rate_limited`、`captcha_required`、`not_found`、`upstream_timeout`、`upstream_unavailable`、`protocol_error`、`internal`。

每个错误映射要写明：是否可重试、是否冷却渠道/模型/账号、建议 HTTP 状态、是否写入审计、是否需要用户重新授权。不得把平台原始错误体、Cookie、token 或 panic 堆栈返回给客户端。

## 8. 契约测试清单

每个 adapter 至少覆盖：

- manifest 字段完整、能力与实际端点一致；
- 模型成功、空目录、格式异常、超时和鉴权失败；
- chat 非流/SSE、取消、上游断流和 usage 缺失；
- 账号 start/poll/complete/import/cancel 的成功、重复、过期、取消、重试和凭据失效；
- 映射不泄露 Secret，`ext` 可序列化且版本兼容；
- 429/5xx/404/连接错误的统一错误分类；
- 新增 fake adapter（`internal/adapters/fake`）后通用 API/UI 无平台专用改动。

契约测试必须使用 `httptest` 等 mock/fake 上游和脱敏 fixture。不得在 CI 依赖三个源项目、真实账号或真实 token。

## 9. 禁止清单

- 在 `internal/transport/http/*.go` 或 Web 组件中写渠道 `if/else`、`switch slug`；
- 在 adapter 中决定 Key 是否授权或跨渠道降级；
- 从 adapter 直接写 SQLite 表或读取 `.env`；
- 把平台 token 放入 API 响应、日志、前端状态、普通数据库列或 `ext`；
- 复制源项目的账号数据、浏览器 profile、Cookie 或密钥；
- 用“能调用旧 HTTP 接口”冒充“已内置”；
- 未声明许可证和依赖许可证就复制源代码或引入库。
