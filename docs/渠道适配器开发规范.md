# 渠道适配器开发规范

本文定义新增平台的唯一扩展入口。新增平台是代码变更，不在管理页面动态执行任意代码。适配器必须能够在没有三个源项目目录、端口和包的环境中独立构建。

## 1. SPI 总览

一个渠道至少由以下对象组成：

```text
ChannelManifest       静态身份、能力、配置 schema、账号流程描述
UpstreamAdapter       模型发现、请求调用、流式响应、能力/错误映射
AccountProvisioner    新增、导入、轮询、完成、取消、刷新和删除账号
CredentialStore port   加密写入、读取引用、轮换和销毁凭据
AccountMapper         平台账号 → canonical Account
ModelMapper           平台模型 → canonical Model
ErrorMapper            平台错误 → canonical ErrorKind
```

建议的 Python 形状（以项目实际 ports 包为准，不要把示例直接放进 router）：

```python
class ChannelManifest(Protocol):
    slug: str
    display_name: str
    adapter_version: str
    protocols: tuple[str, ...]
    capabilities: tuple[str, ...]
    account_flows: tuple[ProvisionFlowSpec, ...]
    config_schema_version: int


class UpstreamAdapter(Protocol):
    manifest: ChannelManifest

    async def health(self, ctx: AdapterContext) -> HealthResult: ...
    async def list_models(self, ctx: AdapterContext) -> list[CanonicalModel]: ...
    async def invoke(self, request: NormalizedRequest, account: AccountRef) -> AdapterResponse: ...
    async def invoke_stream(self, request: NormalizedRequest, account: AccountRef) -> AsyncIterator[Chunk]: ...
    def map_error(self, error: Exception) -> CanonicalError: ...


class AccountProvisioner(Protocol):
    async def describe(self) -> list[ProvisionFlowSpec]: ...
    async def start(self, flow: str, payload: Mapping[str, Any], idem: str) -> ProvisionSession: ...
    async def poll(self, session_id: str, idem: str) -> ProvisionSession: ...
    async def complete(self, session_id: str, payload: Mapping[str, Any], idem: str) -> ProvisionResult: ...
    async def import_accounts(self, payload: Mapping[str, Any], idem: str) -> ProvisionResult: ...
    async def cancel(self, session_id: str, idem: str) -> None: ...
```

`AdapterContext` 只提供 ports（配置、凭据引用、HTTP/browser client、时钟、日志）；adapter 不得直接读取环境变量或全局 SQLite 连接。

## 2. Manifest 契约

每个 manifest 必须声明：

| 字段 | 要求 |
|---|---|
| `slug` | 小写稳定标识，只允许 `[a-z0-9-]`；发布后不改名 |
| `display_name` | 管理面展示名称，不用于路由判断 |
| `adapter_version` | 语义版本；配置或凭据格式变化必须升版本 |
| `protocols` | 实际支持的入站协议，如 `openai`、`anthropic`、`responses` |
| `capabilities` | `chat`、`image`、`video`、`audio`、`file` 等，未实现不得声明 |
| `account_flows` | flow id、类型、字段 schema、是否异步、幂等和权限 |
| `config_schema` | 内置客户端所需配置；Secret 标记为 secret，不回显 |
| `health_checks` | 配置缺失、平台不可达、凭据失效、浏览器故障等状态映射 |
| `limits` | 并发、超时、最大 payload、是否支持重试 |

前端和管理 API 只读取 manifest。新增渠道后，渠道列表、账号筛选、Key 编辑、模型目录和新增账号入口都从 registry 动态生成。

## 4. Registry 规则

registry 是唯一装配点：

```python
ADAPTERS: Mapping[str, RegisteredChannel] = {
    "wb": RegisteredChannel(manifest=..., adapter=..., provisioner=...),
    "doubao": RegisteredChannel(manifest=..., adapter=..., provisioner=...),
    "chatgpt": RegisteredChannel(manifest=..., adapter=..., provisioner=...),
}
```

路由、账号用例、Key 用例和前端不得维护第二份渠道枚举。未知 slug 返回 `404 channel_not_found`；manifest 存在但配置不完整返回 `409 channel_not_configured`；平台短暂不可用映射为 `503/504`。

## 5. 新平台接入步骤

1. 建立 `adapters/<slug>/`，提交 manifest 和配置 schema。
2. 实现 `UpstreamAdapter`：模型、非流式、流式、健康检查、错误映射。
3. 实现 `AccountProvisioner`：至少一个 flow；说明凭据存储、幂等键、超时、取消和审计事件。
4. 实现 mapper，把平台账号/模型/usage 转成 canonical DTO；特有字段只放版本化 `ext`。
5. 在 registry 注册，不修改 gateway/router/application 的平台分支。
6. 添加配置迁移、Secret 模板、契约 fixture 和合规/许可证记录。
7. 增加 adapter contract、错误矩阵、账号流程状态机和最小 E2E。
8. 更新 manifest 文档、OpenAPI、运维告警和变更记录。

若必须修改通用核心，先证明是所有渠道共有的 port/领域规则，并在 ADR 中记录；不得为了一个平台添加 `if slug == ...`。

## 6. 账号 provision 规则

`AccountProvisioner` 的 flow 必须声明：

```json
{
  "id": "oauth-qr",
  "kind": "qr|oauth|token_import|manual",
  "schema": {"type": "object", "properties": {}},
  "supports": {"start": true, "poll": true, "complete": true, "cancel": true},
  "timeout_seconds": 300,
  "idempotency": "required"
}
```

通用账号服务只负责：校验渠道和 flow、生成/校验 idempotency key、持久化会话状态、调用 provisioner、写审计、归一化账号和刷新模型。它不认识 `realm`、`account_id`、`callback`、`access_token` 等平台字段。

## 7. 错误和重试

adapter 必须把平台错误归类为统一 `ErrorKind`：`invalid_request`、`auth_required`、`credential_expired`、`rate_limited`、`captcha_required`、`not_found`、`upstream_timeout`、`upstream_unavailable`、`protocol_error`、`internal`。

每个错误映射要写明：是否可重试、是否冷却渠道/模型/账号、建议 HTTP 状态、是否写入审计、是否需要用户重新授权。不得把平台原始错误体、Cookie、token 或 traceback 返回给客户端。

## 8. 契约测试清单

每个 adapter 至少覆盖：

- manifest 字段完整、能力与实际端点一致；
- 模型成功、空目录、格式异常、超时和鉴权失败；
- chat 非流/SSE、取消、上游断流和 usage 缺失；
- 账号 start/poll/complete/import/cancel 的成功、重复、过期、取消、重试和凭据失效；
- mapper 不泄露 Secret，`ext` 可序列化且版本兼容；
- 429/5xx/404/连接错误的统一错误分类；
- 新增 fake adapter 后通用 API/UI 无平台专用改动。

契约测试必须使用 mock/fake 上游和脱敏 fixture。不得在 CI 依赖三个源项目、真实账号或真实 token。

## 9. 禁止清单

- 在 `routers/admin.py` 或 Web 组件中写渠道 `if/elif`；
- 在 adapter 中决定 Key 是否授权或跨渠道降级；
- 从 adapter 直接写 SQLite 表或读取 `.env`；
- 把平台 token 放入 API 响应、日志、前端状态、普通数据库列或 `ext`；
- 复制源项目的账号数据、浏览器 profile、Cookie 或密钥；
- 用“能调用旧 HTTP 接口”冒充“已内置”；
- 未声明许可证和依赖许可证就复制源代码或引入库。
