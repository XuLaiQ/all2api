# 多媒体接口支持矩阵

> 状态：Go 能力契约、媒体存储和适配器代码已实现；真实 provider E2E 未通过，生产 manifest 只声明 `chat`。
> Python 时期的能力分析和实施计划已归档至 [`archive/python-era/多媒体接口支持矩阵-python.md`](archive/python-era/多媒体接口支持矩阵-python.md)。

## 1. 能力门禁

是否对外开放某项能力只由渠道 manifest 决定（`internal/adapters/registry/registry.go` 中的 `Capabilities`）。`/v1/images/generations`、`/v1/video/generations` 和 `/v1/search` 共用 `internal/transport/http/gateway.go` 的 `capability` handler：

```text
POST /v1/{images,video}/generations | /v1/search
  → 解析 model（<channel>/<model>）和 prompt
  → 网关 Key 认证与 scope 校验
  → manifest 未声明该能力 → 501 capability_not_supported
  → adapter.CapabilityWithAccount（账号池选号）
  → 生成结果写入媒体存储，URL 改写为 /v1/files/{id}/content
  → 记录请求日志
```

渠道 manifest 加入新能力的前提：真实平台调用、CDN 下载和视觉质量 E2E 通过，并在 `docs/migration-evidence/` 留存脱敏证据。

## 3. 接口现状

| 路径 | 当前行为 |
|---|---|
| `POST /v1/images/generations` | 经能力门禁；当前所有渠道返回 `501 capability_not_supported` |
| `POST /v1/video/generations` | 同上 |
| `POST /v1/search` | 同上；未指定 model 时默认 `chatgpt/auto` |
| `GET/POST /v1/files`、`GET/DELETE /v1/files/{id}`、`GET /v1/files/{id}/content` | 已实现：本地文件上传、列表、元数据、删除和下载，按网关 Key 隔离，单文件上限 100 MB |
| `POST /v1/images/edits`、`/v1/audio/generations`、`/v1/files/download` | 返回 `501 capability_not_supported` |
| `POST /v1/ppt/generations`、`/v1/psd/generations`、`/v1/editable-file-tasks` | 返回 `501 capability_not_supported` |
| `POST /v1/messages/count_tokens` | 返回 `501 capability_not_supported` |
| `POST /admin/api/playground/generations`、`/search`、`/editable-file` | 调试台入口，同样受 manifest 门禁 |

## 4. 媒体存储与去水印

- 存储：`internal/infrastructure/media/store.go`，文件位于数据库同级的 `media-assets/` 目录，元数据在 `media_assets` 表；单个素材上限 100 MB。
- 去水印：`POST /admin/api/media/assets/{id}/remove-watermark` 对右下角固定区域执行 Telea 修补（纯 Go 实现，`internal/infrastructure/media/inpaint.go`），输出同尺寸 PNG，另存为 `_clean` 副本，元数据标记 `watermark_method=telea_inpaint`。小于 512×512 的图片原样返回。
- 独立 worker：`cmd/media-worker` 提供 `POST /v1/watermark/remove`，算法相同。

去水印是本地确定性修补，不代表任一 provider 的去水印质量已经验收。

## 5. 开放一项新能力的步骤

1. 在适配器中实现 `CapabilityWithAccount` 对应分支，并补 `httptest` 契约测试（成功、上游错误、超时、结果归一化）。
2. 用 `scripts/probe/` 对真实账号执行脱敏探针，结果存入 `docs/migration-evidence/`。
3. 在 manifest 的 `Capabilities` 中加入该能力，同步更新本文、[API 契约](API契约.md) 和 README 的支持范围。
