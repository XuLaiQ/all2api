# 开发规则 · 页面高度与滚动条

> 适用：所有 Web 界面（详情页 / 列表页 / 表格页 / 网格页一律适用）。
> 来源：pptm2mp4 等项目中反复踩过三轮的实际教训。

## 总则

**主内容区必须撑满「视口高 − 上方已占高度 − 内边距」。**
不允许出现「内容只占上半屏、下面一大片空白」的布局。这是默认要求，不等用户提。

---

## 一、先量，再改

不要凭代码推测，也不要肉眼判断。先跑探针，输出两个数字：

1. **整页溢出**：`document.documentElement.scrollHeight - window.innerHeight`
2. **滚动容器清单**：全 DOM 扫 `overflow-y: auto|scroll` 且 `scrollHeight - clientHeight > 1` 的元素

按结果分三类，**修法完全不同**：

| 症状 | 量出来的样子 | 走哪条路线 |
| --- | --- | --- |
| **整页溢出**（两条滚动条、视口越矮越糟） | `scrollHeight > innerHeight` | 锁 `100dvh` + flex 分配（第三节） |
| **内容不足**（不滚，但下方大片裸背景） | `overflow = 0`，卡片底边离视口底很远 | 撑满剩余高度（第四节） |
| **卡片空壳**（撑满了但卡内一大块空白） | `overflow = 0`，卡片高 ≫ 内容高 | 吃满 + 卡内加 `flex:1` 行列表（第五节） |

出现「视口越矮越糟」的规律 → 基本可断定面板被某个 `clamp()` 的下限卡住了，而整页还在按内容长。

---

## 二、禁止用 `calc` 猜剩余高度

```css
/* ✗ 那个 320 想表达「页头 + 内边距」，实际是 296~390px 浮动 —— 永远调不对 */
height: clamp(520px, calc(100dvh - 320px), 860px);
```

修法不是把数字改准，而是**让浏览器自己算**：整页锁成 `100dvh`，用 flex 把剩余高度交给面板。

---

## 三、整页锁高的标准写法

```css
.page { height: 100dvh; display: flex; flex-direction: column; }
.page > .header { flex: 0 0 auto; }

.page > .body { flex: 1; min-height: 0; }        /* ★ min-height:0 是承重行 */
.page > .body > .sidebar,
.page > .body > .main { min-height: 0; overflow-y: auto; }
```

要点：

- **`min-height: 0` 不能省。** flex 子项默认 `min-height: auto`，不写 `0` 就撑破容器，整页照样溢出。
- **但它不是万能药**：不要无脑加在**卡片网格的卡片**上 —— 会让行的最小尺寸归零，网格一滚动卡片就被压扁。只加在 flex 子项 / 卡体 / 页根上。
- **内容不足一屏的页面不要套 `100dvh`**（会把短页面压成一屏高、内容反而被裁），走第四节。
- **窄屏必须给回退**：两栏堆叠断点、手机断点退回自然文档滚动。
- 不要用 `overflow: hidden` 直接砍掉整页滚动 —— 内容真超出时用户就彻底看不到了。锁高 + 内部滚动才既能无整页滚动条、内容也还能滚。

---

## 四、撑满剩余高度（内容不足型）

JS 实测：

```js
const h = window.innerHeight - main.getBoundingClientRect().top - padBottom - tailHeight;
main.style.minHeight = Math.round(h) + 'px';
main.querySelectorAll(':scope > .card').forEach((c) => { c.style.maxHeight = h + 'px'; });
```

**四个必须同时满足：**

1. **`min-height` 与 `max-height` 成对。** 只写 min → 长列表把容器撑破；只写 max → 内容被压扁。
2. **`max-height` 必须配 `overflow: hidden`**（卡片）+ 主体 `overflow-y: auto`。否则溢出到盒子**之外**的内容会撑大父级 `scrollHeight`，表现为「元素明明都在视口内、整页却能滚」。
3. **不要写「内容是否超屏」的分支。** `min-height` 天然处理：内容更高时不压缩。超一屏的页面自动免疫。
4. **主容器取第一个，并扣掉尾部兄弟的高度（含间距）。** 查找范围要覆盖「外面包了一层 wrapper」的情况。

**更稳的纯 CSS 版**（优先选）：

```css
.content { display: flex; flex-direction: column; }
.content > .page { flex: 1 1 auto; min-height: 0; display: flex; flex-direction: column; }
.page-fill { flex: 1 1 0; min-height: 260px; }   /* ★ basis 必须是 0 */
```

> ★ **`.page-fill` 的 `flex-basis` 必须是 `0`，不能写 `auto`。**
> 写 `auto` 时区块对页根内容高度的贡献 = 自己的内容高度；区块是网格、行是
> `grid-auto-rows: minmax(auto, 1fr)`，容器高度不确定 → `1fr` 按规范退化成 `max-content`
> → 长表格把整页顶高（实测 239px → **868px，比不修还糟**）。

**撑满容器 ≠ 内容填满。** 卡片拉高后内部仍是空白，这是预期效果（比原来的灰底空白更整体）。
不要为了「填满」把网格行 / 表格行强行拉伸。

---

## 五、卡片网格：吃满 + 卡内放列表，不是二选一

卡片本身通常只有 ~160px 内容，**直接撑高必然空壳**；**退回内容高度又会在页面下方留大片裸背景**。
真正能吸收任意高度的只有「行结构」，所以正解是两者同时满足：

```css
.grid {
  grid-template-columns: repeat(auto-fit, minmax(520px, 1fr));
  grid-auto-rows: minmax(300px, 1fr);
  align-content: stretch;
  overflow-y: auto;
}
.grid > .card { display: flex; flex-direction: column; }              /* 不要 min-height:0 */
.grid > .card > .feed { flex: 1; min-height: 0; overflow-y: auto; }   /* 吸收剩余高度 */
.grid > .card > .actions { margin-top: auto; }                        /* 操作行钉底 */
```

- **列数用 `auto-fit`，不要 `repeat(2, 1fr)`。** 后者单张卡只占左半栏、右半栏整片空着（用户截图里最刺眼的地方）。`N` 取「操作行不折行的最小宽度」，**要实测**。
- **行高下限必须写死像素。** 写 `max-content` → 卡片缩回内容高度，页面下方又留白；写 `minmax(auto,1fr)` → 卡片带 `min-height:0` 时最小尺寸归零，网格一滚动就被压扁。
- **卡内那块 `flex:1` 必须是行结构**（日志行、明细字段网格），**不能是空白 `div`** —— 空白 `div` 只是把空壳从「内容之间的空白」换成「内容下面的一大块背景」，观感一样差。**动手前先确认这个页面有行级数据源**；没有的话这个区块就不该吃满。
- **钉底优先 `margin-top: auto`，不要 `justify-content: space-between`。** 后者会把每个子块都摊开，看起来像样式坏了。两者不能并存：auto 外边距会吃掉全部剩余空间，`space-between` 静默失效。

## 六、验收：三个数字必须都为 0

1. **整页溢出 = 0**（每个视口 × 每个路由）
2. **卡内空白 = 0**：`卡片内高 − Σ子元素高 − gap×(n−1)`
3. **网格内空白 = 0**：`网格内高 − Σ行轨道高 − gap×(行数−1)`

> **两个空白必须同时量。** 实测有一版卡内空白 0、卡片尺寸也正常，空白全在卡片**外面**的网格里（540px）—— 只量卡内会完全漏掉。

**两个写错过的指标，别再用：**

- 「卡片高 − 操作行底边」→ 只量到下内边距，永远 ≈7%，全绿但什么也没测。
- 「操作行顶边 − 数据块底边」→ 卡内列表正好长在两者之间时**语义反转**，数字越大越说明填满了。

---

## 七、其他必查项

- **层叠源码顺序。** 同一组件里多个 `<style scoped>` 块编译后共享同一 `data-v-*`，特异性完全相同，胜负**只由源码顺序决定**。新增覆盖块一律**追加到文件末尾**；顺序错了零报错，只是悄悄多一条滚动条。
- **内联 `style` 特异性高于样式表。** 残留的 `align-items:start` / `max-height:420px` 会静默顶掉新契约，改完样式回头搜一遍内联写法。
- **内部滚动 + 定时重渲染 = 滚动位置每 N 秒归零。** 用 `innerHTML = render()` 的面板，把 `scrollTop` 存/恢复。
- **`overflow-x: auto` 会把 `overflow-y: visible` 计算成 `auto`**，等于多造一个滚动容器。排查意外滚动条时留意媒体查询里的 `overflow-x`。
- **静态 HTML 改完截图没变化，先怀疑缓存**，URL 加 `&_t=<Date.now()>`。
- **改完必须重跑构建再验证**，别拿旧产物下结论。
