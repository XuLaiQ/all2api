# 项目开发基线

## 1. 项目定义

All2API 是一个单一代码仓库、单一交付物和单一管理面的模块化单体网关。WorkBuddy、Doubao、ChatGPT 三个源项目只用于一次性审计、行为提取和迁移验证；它们的目录、进程、端口、数据库、凭据文件和包不能成为运行时依赖。

“单一项目”不等于“所有逻辑必须同一进程”。浏览器或平台专用 worker 可以独立进程，但必须由本仓库构建、配置、启动和监控，且只能经本项目定义的 ports/内部协议通信。

硬约束：`外置源项目依赖 = 0；内部进程边界 >= 1`。

## 2. 需求追踪矩阵

| 编号 | 必须交付 | 代码/文档落点 | 禁止事项 | 验收证据 |
|---|---|---|---|---|
| REQ-CH-01 | 三渠道在同一管理面独立管理 | `ChannelManifest`、`ChannelRepository`、渠道 API/UI | 为每个平台复制核心表或页面 | 三个渠道均可读写/同步，能力来自注册表 |
| REQ-KEY-01 | 一个 `/v1` URL + 网关 Key 调用三渠道 | gateway auth/router、Key `channels/models` scope | 把上游 Key 暴露给调用方；alias 绕过授权 | 同一 Key 分别调用三渠道；未授权返回 403 |
| REQ-EXT-01 | 新平台通过代码扩展 | `app/adapters/<slug>`、registry、契约测试 | 核心路由写平台 `if/elif` | fake adapter 注册后通用 UI/API 自动可用 |
| REQ-ACC-01 | 新增账号先选渠道，再显示渠道流程 | `AccountProvisioner`、动态 schema、账号页面 | 通用表单硬编码三套平台字段 | 三渠道 start/poll/complete/import 成功/失败/取消可测 |
| REQ-STD-01 | 企业级目录、依赖、测试、CI | 工程规范、架构检查、迁移脚本 | domain 依赖 FastAPI/httpx/源包 | lint/typecheck/test/SBOM/许可证门禁通过 |
| REQ-DEP-01 | 源项目断开后仍可运行 | 内置 adapter/worker、独立配置 | `F:\token-p` 路径、源端口、源 DB/import | 删除源目录、清空 bridge 配置后 clean build/run |

## 3. 首版范围与非目标

首版必须同时具备：三渠道注册和能力声明、统一模型目录、统一 `/v1` 数据面、Key 渠道授权、账号新增渠道选择、凭据安全存储、请求日志和审计。新增平台是代码变更，不要求在页面动态编程。

首版不要求：多租户云托管、跨节点分布式调度、直接读取源项目数据库、把源项目作为 Git submodule、在 UI 中编写新适配器。

上游平台本身（WorkBuddy/Doubao/ChatGPT 官方服务、网络和浏览器验证）仍可能是业务外部依赖；“不依赖三个项目”指不依赖三个开源/本地反代项目，而不是承诺离线调用第三方平台。

## 4. 目标模块边界

| 层 | 责任 | 依赖规则 |
|---|---|---|
| `web/` | 展示、动态表单、请求状态 | 只调用管理 API，不做授权/调度 |
| `routers/` | HTTP schema、认证、响应映射 | 不直接 import 具体 adapter |
| `application/` | 用例编排、事务、审计 | 依赖 domain 和 ports |
| `domain/` | Channel/Account/Key/Request 规则 | 不依赖 FastAPI、httpx、SQLite、Playwright |
| `ports/` | Adapter、Provisioner、Repository、CredentialStore 接口 | 只定义稳定协议 |
| `adapters/` | 三渠道平台私有实现 | 实现 ports，不做跨渠道路由 |
| `infrastructure/` | HTTP、数据库、加密、浏览器 worker | 由依赖注入装配 |

当前代码仍是过渡形态，详见[目标架构与迁移方案](目标架构与迁移方案.md)和[企业开发规范](企业开发规范.md)；未完成迁移的实现不得宣称已满足目标态。

## 5. 开发阶段与 DoD

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| M0 基线 | 目录、契约、来源审计、许可证清单 | 需求矩阵冻结，源目录仅读，fixture 建立 |
| M1 内核 | domain/ports、registry、Key/router、SQLite 迁移 | fake adapter 可注册；核心无平台分支 |
| M2 WorkBuddy | QR OAuth、realm、凭据轮换、模型/聊天 | 源项目离线可构建；行为契约通过 |
| M3 Doubao | profile、QR、Playwright/browser worker、SSE | 浏览器资源由本项目管理；失败/验证码可恢复 |
| M4 ChatGPT | OAuth PKCE、token import/refresh、协议和模型 | token 不回显；并发/刷新测试通过 |
| M5 切换 | 数据导入、feature flag、停用 bridge | 三源端口关闭仍能完整运行 |
| M6 扩展 | fake/示例平台、发布和运维 | 新平台只改 adapter/manifest/测试/配置 |

每个阶段 DoD：实现、OpenAPI、数据库迁移、前端类型、测试、审计事件和运维说明同步；不允许把“设计完成”当成“代码完成”。

## 6. Definition of Ready

- 目标、范围外事项、验收证据和回滚路径明确；
- API DTO、权限、幂等、错误和副作用写入契约；
- 平台私有逻辑归属到 adapter/provisioner，未散落到 router/UI；
- 凭据生命周期、日志脱敏、存储和删除策略已评审；
- 来源代码版本、文件、许可证和可迁移行为已记录。

## 7. Definition of Done

- `pnpm lint && pnpm typecheck && pnpm build` 通过；
- `uv run ruff check . && uv run pytest` 通过，适配器契约和安全测试覆盖变更；
- 数据库迁移可重复、可回滚或有明确前向兼容策略；
- 无明文 Secret、Cookie、OAuth token、浏览器 profile、绝对源路径进入 Git、响应或日志；
- `rg` 检查不允许运行时代码出现源项目 import、源端口或 `F:\token-p`；
- 断开源目录和源端口后重新安装、构建、测试、启动；
- PR 记录变更范围、风险、测试命令、API/DB 文档和迁移来源。

## 8. 测试分层

后端包括 domain/application 单元测试、SQLite 集成测试、每个 adapter 的 mock 上游契约测试、账号流程状态机测试和安全测试；前端包括动态渠道 schema、Key scope、权限、加载/错误/取消状态；E2E 覆盖登录、选渠道新增账号、创建 Key、三渠道调用和未授权拒绝。

## 9. 当前状态声明

当前 checkout 已有三渠道外部 HTTP bridge、部分统一网关和管理页面，但尚未达到“源项目零依赖”的目标态。`registry.py` 和 `provisioning.py` 仍以 URL/key 为中心，`admin.py` 仍有渠道分支；这些是 M1-M4 的迁移任务，不是目标架构的范例。
