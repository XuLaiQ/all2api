# 项目开发基线

## 项目状态

本项目把三个已经具备反向代理能力的独立项目接入同一个管理面和统一调用入口。前后端在本仓库分别开发、分别管理依赖，通过 HTTP API 集成。当前 Web 工程可启动；API 已有 SQLite schema、三渠道适配器、模型/聊天路由、账号聚合、管理会话、别名跨渠道降级和 WorkBuddy 请求归因。WorkBuddy 已接入同步快照候选、进程内账号租约和上游严格定向选号；Doubao/ChatGPT 的账号级调度与真实三渠道凭据验收仍待完成。文档中的目标架构不代表未实现功能已经可用。

## 目标与首期范围

三个基线反代项目及其现有能力来源：

| 渠道 | 现有项目 | 本项目接入方式 |
|---|---|---|
| WorkBuddy | `F:\token-p\WorkBuddy\wb2api` | 通过其 HTTP 数据面和管理面接入 |
| doubao | `F:\token-p\反代\doubao2api` | 通过其 HTTP 数据面和管理面接入 |
| chatgpt | `F:\token-p\chatgpt2api` | 通过其 HTTP 数据面和管理面接入 |

三套现有反代继续各自运行并负责上游协议、账号凭据和平台专有逻辑；All2API 不把它们的进程或依赖树合并。网关负责统一渠道/账号管理、模型路由与调度，并提供一个对外 API Base URL 和由网关签发的 API Key。调用方不需要分别配置三家上游地址或上游凭据。

首个可交付版本必须同时满足以下三项：

1. **统一管理三渠道**：在同一管理面查看和配置 WorkBuddy、doubao、chatgpt 渠道及其上游账号、模型能力、启用状态与健康状态；管理操作通过各自管理 API 执行。
2. **统一调用入口**：对外提供单一 Gateway Base URL（默认 `http://localhost:8080/v1`）及网关签发的 `sk-a2a-*` API Key；请求模型名决定走指定渠道模型或已配置的路由别名。上游凭据不暴露给调用方。
3. **可插拔扩展**：新增平台实现并注册适配器后，能进入统一渠道、账号、模型、路由和日志流程；不得为每个平台复制一套网关核心或另建专用数据表。

管理控制台、请求日志、用量、调试台、权限和审计是上述目标的配套管理能力。各渠道可用协议与多模态能力由适配器声明；网关只对调用方公开当前已接入且确实可用的能力。

M1 先用 WorkBuddy 验证接入契约，M2 再完成 doubao 与 chatgpt；这只是实现顺序。三家全部接入并能通过同一 URL + 网关 API Key 调用，才算首个版本达到范围。首期不做 Redis、消息队列、多租户、云端托管控制面、直接连接上游数据库或绕过上游管理 API 读取凭据。完整域模型和适配器规则由[系统设计与实现文档](系统设计与实现文档.md)定义。

## 架构边界

| 部分 | 路径 | 负责 | 不负责 |
|---|---|---|---|
| Web | `web/` | 页面、路由、输入校验、请求状态、管理面交互 | 调度、授权裁决、持久化、上游凭据 |
| Gateway API | `services/api/` | 鉴权、授权、校验、调度、协议转换、审计、持久化 | 页面状态与浏览器缓存 |
| SQLite | API 数据目录 | 渠道/账号/模型/路由/密钥元数据、日志、用量和审计 | 客户端直接访问 |
| Upstream adapters | `services/api/app/adapters/` | 上游 API 差异、错误映射、账号同步 | 跨渠道路由决策 |
| Compose | 根 `docker-compose.yml` | 本地联调拓扑、持久化卷、端口映射 | 生产密钥与生产部署策略 |

数据库/API 是业务事实来源。浏览器状态只保存筛选、展开状态和未提交表单；正式数据不进入 localStorage。上游凭据只在 API 环境中配置。

## 工作区与工具链

- JavaScript：pnpm 10 workspace，目前只有 `web/`。
- Web：React 19、TypeScript strict、Vite 6、React Router 7、Axios 1、ESLint 9。
- Python：Python 3.13.x、uv、FastAPI、Pydantic Settings、httpx、SQLite 标准库。
- 本地依赖：Node.js 20.19+、pnpm 10、Python 3.13.x、uv；Compose 需要 Docker Compose v2。
- 前后端分别运行：Web 默认 `5173`，API 默认 `8080`；开发时由 Vite 代理 `/admin/api` 和 `/v1`。

完整命令见根 [README](../README.md)、[前端开发准备](前端开发准备.md) 与 [后端说明](../services/api/README.md)。

## 环境配置

| 文件 | 用途 | 规则 |
|---|---|---|
| 根 `.env.example` | Compose 端口、容器内 API 地址、管理员登录与可信代理配置 | 复制为根 `.env`；只放本机开发值 |
| `web/.env.example` | Vite proxy target 与公开 API 路径 | 复制为 `web/.env.local`；`VITE_*` 会进入浏览器构建，禁止放 Secret |
| `services/api/.env.example` | API 服务、数据库、安全与上游凭据 | 复制为 `services/api/.env`；生产必须替换默认 session secret |

Compose 通过 `api_data` 卷保存数据库与运行态；上游凭据不写入镜像。生产环境还需单独配置 HTTPS、备份、可信代理与密钥轮换。

## 开发顺序与阶段验收

阶段顺序以系统设计 §12 为准；每阶段必须满足验收后再开始依赖它的页面/模块。

| 阶段 | 前后端交付 | 验收门槛 |
|---|---|---|
| M0 准备 | 范围、域模型、API 契约、环境与启动方式 | 文档互相一致；本地/Compose 前后端启动；契约无未决字段 |
| M1 骨架与 WorkBuddy | 配置、健康检查、SQLite schema/迁移、会话、单渠道聊天 | `/admin/api/healthz`、会话流程与 `wb` 数据面可运行；关键失败路径有覆盖；此阶段不代表首版范围完成 |
| M2 三渠道与调度 | Doubao、ChatGPT 适配器，账号池、冷却、熔断、降级 | 三渠道都可管理，并通过统一 URL + 网关 API Key 调用；并发与失败分类符合设计；这是首版范围门槛 |
| M3 协议与计量 | 流式、多协议、日志、用量聚合与保留清理 | SSE 可取消；数据面错误格式兼容；日志与用量可对账 |
| M4 管理面 | 完整管理 API、角色/审计、批量操作、设置 | API 清单均有实现；`admin` 与 `viewer` 权限逐项验证 |
| M5 Web 与发布准备 | 原型拆分成页面、真实 API 联调、可观测与运维说明 | 三个基线渠道在管理面可配置；一条 Base URL/API Key 调用三渠道模型；增加一个测试适配器不改网关核心与通用管理 UI；页面与运维验收通过 |

## Definition of Ready

开始一个业务任务前，检查：

- 目标用户、范围外事项和验收标准明确。
- 所需 API method/path、请求/响应 DTO、权限和错误状态已在契约中定义。
- 数据存储、迁移、幂等、副作用和回滚行为明确。
- UI 有对应原型/状态说明；加载、空、错误、权限不足和成功状态均有定义。
- 依赖、环境变量、启动方式与运行日志可复现。

任一项不满足时，先补设计/契约，再实现业务逻辑。

## Definition of Done

- 前后端实现与 OpenAPI、域模型和验收标准一致。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过；后端 `uv run ruff check .`、`uv run pytest` 通过。
- API 合同/DB 变更同步文档；迁移可重复执行，关键写操作有审计与失败恢复路径。
- 401/403、校验错误、冲突、上游超时/不可用和重试路径经过验证。
- 无 Secret 入库；日志不记录明文密钥、Cookie 或上游凭据。
- Compose 与本地启动流程可复现，交付说明记录运行命令和已知限制。

## 测试分层

- 后端单元：错误分类、账号状态机、选号/冷却、权限、配置校验、迁移。
- 后端集成：FastAPI TestClient/httpx + 临时 SQLite，覆盖认证、隔离、事务和 API schema。
- 适配器契约：模拟上游，覆盖成功、限流、凭据失效、超时、格式异常和取消。
- 前端单元/组件：Vitest + Testing Library，覆盖 API client、权限态、表单校验、加载/空/错误状态。
- 端到端：Playwright，覆盖登录、渠道/账号管理、路由、密钥创建、日志查询与会话过期。
- 改动时至少跑受影响层；合并门禁跑 lint、类型检查、构建和完整后端测试。测试依赖在对应阶段加入，不提前安装未用工具。

## 已知限制

- 当前 API 已连接 SQLite 并提供三渠道数据面与 Cookie 管理会话。WorkBuddy 真实调用及请求级账号归因已通过；网关现按同步快照对 WB 做有限候选选择，并要求上游用共享追踪密钥校验定向账号、通过并发租约后回报实际账号。定向选号的双端运行验证仍待配置可用上游后完成。Doubao/ChatGPT 的真实成功路径仍受上游风控/额度阻塞，且缺少可信逐请求账号标识；网关暂不对其账号级调度或渠道级失败作账号归因。
- 根 Compose 是本地开发拓扑，不是生产部署模板。
- 当前工作目录未配置 Git remote/CI 流程；进入团队协作前需确定仓库托管与分支/评审门禁。
