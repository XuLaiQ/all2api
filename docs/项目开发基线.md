# 项目开发基线

## 1. 项目定义

All2API 是一个单一代码仓库、单一交付物和单一管理面的模块化单体网关，后端由 Go 实现。WorkBuddy、Doubao、ChatGPT、Grok 的参考项目只用于一次性审计、行为提取和迁移验证；它们的目录、进程、端口、数据库、凭据文件和包不能成为运行时依赖。

“单一项目”不等于“所有逻辑必须同一进程”。浏览器或媒体 worker（`cmd/doubao-browser-worker`、`cmd/media-worker`）是独立进程，但由本仓库构建、配置、启动和监控，且只经本项目定义的内部协议通信。

硬约束：`外置源项目依赖 = 0；内部进程边界 >= 1`。

## 2. 需求追踪矩阵

| 编号 | 必须交付 | 代码/文档落点 | 禁止事项 | 验收证据 |
|---|---|---|---|---|
| REQ-CH-01 | 多渠道在同一管理面独立管理 | `ports.AdapterManifest`、`internal/adapters/registry`、渠道 API/UI | 为每个平台复制核心表或页面 | 各渠道均可读写，能力来自注册表 |
| REQ-KEY-01 | 一个 `/v1` URL + 网关 Key 调用所有渠道 | `internal/application/gateway`、Key `channels/models` scope | 把上游 Key 暴露给调用方；alias 绕过授权 | 同一 Key 分别调用各渠道；未授权返回 403 |
| REQ-EXT-01 | 新平台通过代码扩展 | `internal/adapters/<slug>/`、registry、契约测试 | 核心路由写平台 `if/else` | fake adapter 注册后通用 UI/API 自动可用 |
| REQ-ACC-01 | 新增账号先选渠道，再显示渠道流程 | provisioner、动态 provision schema、账号页面 | 通用表单硬编码平台字段 | start/poll/complete/import 成功/失败/取消可测 |
| REQ-STD-01 | 企业级目录、依赖、测试、CI | [企业开发规范](企业开发规范.md)、`tools/`、`scripts/verify/` | domain 依赖 HTTP、SQLite 或源项目包 | gofmt/vet/test、lint/typecheck/build、SBOM/许可证门禁通过 |
| REQ-DEP-01 | 源项目断开后仍可运行 | 内置 adapter/worker、独立配置 | 源项目路径、源端口、源 DB | `scripts/verify/verify-go-clean-build.ps1` 在临时目录构建并启动 |

## 3. 首版范围与非目标

首版必须同时具备：渠道注册和能力声明、统一模型目录、统一 `/v1` 数据面、Key 渠道授权、账号新增渠道选择、凭据安全存储、请求日志和审计。新增平台是代码变更，不要求在页面动态编程。

首版不要求：多租户云托管、跨节点分布式调度、读取源项目数据库、把源项目作为 Git submodule、在 UI 中编写新适配器。

上游平台本身（官方服务、网络和浏览器验证）仍是业务外部依赖；“不依赖源项目”指不依赖开源/本地反代项目，而不是承诺离线调用第三方平台。

## 4. 模块边界

| 层 | 目录 | 责任 | 依赖规则 |
|---|---|---|---|
| Web | `web/` | 展示、动态表单、请求状态 | 只调用管理 API，不做授权/调度 |
| 传输 | `internal/transport/http/` | HTTP 路由、认证、请求解析、响应映射 | 不直接 import 具体渠道 adapter 的平台逻辑 |
| 应用 | `internal/application/` | 用例编排、事务、审计 | 依赖 domain 和 ports |
| 领域 | `internal/domain/` | scope 等纯规则 | 不依赖 HTTP、SQLite、浏览器 |
| 端口 | `internal/ports/` | Adapter、Provisioner、Repository、SecretBox 接口 | 只定义稳定协议 |
| 适配器 | `internal/adapters/` | 各渠道平台私有实现 | 实现 ports，不做跨渠道路由 |
| 基础设施 | `internal/infrastructure/` | SQLite、加密、媒体、Token 估算、安全 | 在 `cmd/all2api/main.go` 装配 |

## 5. 开发阶段与 DoD

| 阶段 | 交付 | 状态 |
|---|---|---|
| M0 基线 | 目录、契约、来源审计、许可证清单 | 完成 |
| M1 内核 | domain/ports、registry、Key/router、SQLite 迁移 | 完成 |
| M2 WorkBuddy | QR OAuth、realm、凭据轮换、模型/聊天 | 本地契约通过；真实平台 E2E 待验收 |
| M3 Doubao | QR、浏览器 worker、SSE | 本地契约通过；浏览器认证 E2E 待验收 |
| M4 ChatGPT / Grok | OAuth PKCE、token import/refresh、协议和模型 | 本地契约通过；真实平台 E2E 待验收 |
| M5 切换 | Go 唯一运行时，删除 Python 后端和 legacy bridge | 完成 |
| M6 扩展与发布 | fake/示例平台、CI、发布和运维 | 进行中，见 `scripts/verify/check-release-readiness.ps1` |

每个阶段 DoD：实现、API 契约、数据库迁移、前端类型、测试、审计事件和运维说明同步；不允许把“设计完成”当成“代码完成”。

## 6. Definition of Ready

- 目标、范围外事项、验收证据和回滚路径明确；
- API DTO、权限、幂等、错误和副作用写入契约；
- 平台私有逻辑归属到 adapter/provisioner，未散落到 handler/UI；
- 凭据生命周期、日志脱敏、存储和删除策略已评审；
- 来源代码版本、文件、许可证和可迁移行为已记录。

## 7. Definition of Done

- `gofmt -l cmd internal tools` 无输出，`go vet ./...`、`go test ./...` 通过；
- `pnpm --dir web lint && pnpm --dir web typecheck && pnpm --dir web build` 通过；
- 适配器契约和安全测试覆盖变更；新增公开路由同时登记到 `docs/migration-baseline/routes.json`；
- 数据库迁移可重复执行，或有明确的前向兼容策略；
- 无明文 Secret、Cookie、OAuth token、浏览器 profile、绝对源路径进入 Git、响应或日志；
- `go run ./tools/doclinks` 通过；
- PR 记录变更范围、风险、测试命令、API/DB 文档和迁移来源。

## 8. 测试分层

Go 测试与实现放在同一包内（`*_test.go`）：

- domain/application 单元测试；
- `internal/infrastructure/persistence` 的 SQLite 集成测试（临时数据库）；
- 每个 adapter 的 mock 上游契约测试（`httptest`）；
- 账号流程状态机和安全测试；
- `internal/transport/http` 的 HTTP 契约测试，以及 `route_coverage_test.go` 对 `routes.json` 的路由覆盖检查。

前端覆盖动态渠道 schema、Key scope、权限、加载/错误/取消状态。真实平台 E2E 使用 `scripts/probe/` 中的脱敏探针单独执行，不进入普通 `go test`。

## 9. 当前状态声明

Go 是唯一后端运行时。已具备：四渠道 manifest/provision schema、统一 Key scope、schema 驱动账号表单、native adapter/provisioner、二维码状态机、Fernet 凭据存储、本地账号池、SQLite provision session、bootstrap Key 同步、Token 本地估算和 Telea 去水印。Python 后端和 legacy bridge 已删除，生产环境会拒绝残留的 legacy 变量。

尚未完成：各渠道真实平台 E2E、上游凭据轮换和浏览器认证恢复、多媒体能力的真实 provider 验收、CI 流水线和根目录 LICENSE。不能把本地契约通过误认为发布完成。

需求入口是[统一平台整合需求说明](统一平台整合需求说明.md)。迁移过程的历史记录见 [`archive/python-era/`](archive/python-era/)。
