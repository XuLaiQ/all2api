# 部署运维与验收

## 1. 目标交付形态

生产只交付 All2API 自己构建的镜像/包和受控数据卷：

```text
all2api-web + all2api-api
        ├─ SQLite / migrations
        ├─ encrypted credential store
        ├─ optional browser worker (由本仓库镜像管理)
        └─ optional platform worker (由本仓库镜像管理)
```

三个源项目不是 compose service、sidecar、volume、submodule 或健康检查依赖。目标部署中不暴露它们的端口，也不挂载它们的目录。

## 2. 环境配置原则

目标配置分为：

| 类别 | 示例 | 规则 |
|---|---|---|
| 服务 | `A2A_HOST`、`A2A_PORT`、CORS | 可提交模板，生产覆盖 |
| 存储 | DB、credential store、备份目录 | 绝对路径只在部署层配置 |
| 安全 | session secret、admin、加密主密钥 | Secret manager 注入，不进镜像 |
| 渠道内置客户端 | 官方平台地址、OAuth client、browser executable、worker 并发 | 按 manifest schema 校验 |
| 兼容 bridge（迁移期） | `A2A_LEGACY_BRIDGE_ENABLED` 等 | 默认 false；只用于迁移对照，发布前删除/隔离 |

旧的 `A2A_*_UPSTREAM_BASE`、外部管理 token 和源项目数据库路径只可存在于迁移 profile，不得作为生产模板的必填项。
当前模板把它们隔离在 `A2A_LEGACY_*`/deprecated 区域并置空；最终删除兼容 transport 时一并删除这些变量。

native 账号凭据由 `A2A_CREDENTIAL_MASTER_KEY` 加密后写入本项目 `credentials` 表；数据库只保存密文和引用，账号表的 `ext` 只保存 `credential_ref`。恢复备份时必须同时恢复数据库和同一主密钥，主密钥丢失时不得尝试从数据库推导。

### 当前配置边界（已实现）

服务现在将渠道配置分为两组：

- `A2A_*_PLATFORM_BASE`（以及 WorkBuddy 的 `A2A_WB_PLATFORM_DATA_KEY`）由本项目内置
  adapter/provisioner 使用，指向官方平台协议端点；native 账号新增不会读取旧项目管理端口。
- `A2A_LEGACY_BRIDGE_ENABLED` 与 `A2A_LEGACY_*` 只用于迁移期 HTTP bridge，默认 `false`。
  旧的 `A2A_WB_UPSTREAM_*`、`A2A_DOUBAO_UPSTREAM_*`、`A2A_CHATGPT_UPSTREAM_*` 仅作兼容别名。

当总开关关闭时，旧 `/admin/api/accounts/{channel}/onboarding/*` 路由返回 `410`，不会访问兼容上游；
应使用 `/admin/api/channels/{channel}/accounts/provision/*` native 路由。生产部署
必须保持该开关关闭，并且不设置 `A2A_LEGACY_*` 凭据。

## 3. 启动和健康检查

启动顺序：

1. 校验配置 schema 和 Secret 强度；
2. 执行/验证数据库迁移；
3. 初始化 CredentialStore、registry 和 worker；
4. 启动 `/admin/api/healthz`、指标和日志；
5. 按需执行显式渠道测试，不在页面初次加载时自动探测。

健康状态至少区分：

```text
ready                 服务、存储、registry 正常
degraded              某渠道配置/凭据/worker 不可用，其他渠道可用
not_configured        渠道未完成内置配置
platform_unavailable  官方平台网络/服务不可达
storage_error         DB 或凭据存储不可读
```

健康接口不得返回 Secret、绝对源路径、token、profile 内容或原始上游错误。

## 4. 备份、恢复和保留

- SQLite、迁移版本、加密凭据数据和配置 schema 作为一致性备份单元；
- 备份前暂停破坏性账号操作或使用事务快照；
- 加密主密钥与数据库分开保存，恢复演练必须验证能解密凭据；
- 请求日志、usage 和审计按配置保留，Key hash 可保留但明文不可恢复；
- 删除账号/渠道先生成审计摘要，再销毁凭据和 profile；
- 每月至少一次在隔离环境恢复最新备份并执行三渠道健康和 Key 授权测试。

## 5. 观测和告警

结构化日志/指标至少包含：

- `request_id`, `channel`, `model`, `adapter_version`, `status`, `error_kind`；
- latency、TTFT、stream interrupted、usage known/unknown；
- 账号池可用数、租约、冷却、熔断和凭据过期数量；
- provision session 成功/失败/过期/取消和耗时；
- browser worker 崩溃、内存、上下文数、验证码等待时间。

告警不应把 token、Cookie、callback 或完整账号 id 放进消息。渠道失败必须能区分 adapter bug、配置缺失、凭据失效和官方平台不可用。

## 6. 迁移发布顺序

```text
审计/fixture → native adapter contract → 单渠道灰度
→ 三渠道真实平台 E2E → 通过本地 provision 流程写入经确认的账号 → 停止 bridge
→ 关闭源端口/卸载源目录 → clean build/run → 正式发布
```

迁移期间可以用脱敏请求/响应 fixture 做 shadow compare，但不得把真实 token 或账号数据写入测试仓库。出现问题时回滚 adapter/feature flag；不要恢复对源项目的生产运行依赖作为长期方案。

## 7. 发布验收矩阵

| 类别 | 验收条件 | 证据 |
|---|---|---|
| 源项目隔离 | 三源目录删除/改名、端口停止、环境变量清空后仍能启动 | clean checkout 日志、CI job |
| 三渠道管理 | 渠道、模型、账号状态在同一管理面可区分 | API 响应、截图、审计 |
| 统一调用 | 同一 `/v1` URL + 一把授权 Key 调用 `wb/*`、`doubao/*`、`chatgpt/*` | 三组请求/响应和 request log |
| Key 授权 | 单渠道 Key 跨渠道 403；alias 不绕过；轮换立即失效 | 自动化测试 |
| 账号新增 | 先选渠道；WB QR、Doubao QR/profile、ChatGPT OAuth/token flow 均可成功/失败/取消/重试；账号列表只读取本地目录，旧同步接口不存在 | E2E、脱敏 session 记录、`/admin/api/accounts/sync` 404 |
| 凭据安全 | API、日志、DB dump、前端 bundle 无明文 token/Cookie/Key | secret scanner 报告 |
| 扩展性 | 注册 fake adapter 只新增 adapter/manifest/配置/测试 | diff + contract test |
| 工程质量 | lint/typecheck/build/ruff/pytest、迁移和许可证扫描通过 | CI 产物 |
| 运维 | 备份恢复、健康、指标、日志保留和告警演练通过 | runbook/演练记录 |

## 8. 无源项目验证脚本思路

仓库提供可重复执行的门禁脚本，脚本会在随机端口启动临时 API 和临时
SQLite 数据库，不会读取或修改开发者现有的 `services/api/.env`，也不会占用
默认的 8080 端口：

```powershell
python scripts/verify-clean-build.py
# Windows 开发机也可以使用包装脚本
.\scripts\verify-clean-build.ps1
```

CI 额外验证 Compose 语法和 Docker 构建：

```powershell
python scripts/verify-clean-build.py --docker
```

门禁会检查运行时代码没有源项目路径/管理端口和已删除的账号同步接口、两个已提交环境模板中的
legacy upstream 变量为空、`A2A_LEGACY_BRIDGE_ENABLED=false`，并确认
`GET /admin/api/healthz` 返回数据库正常。Docker 不可用时，本地可省略
`--docker`，但发布 CI 必须启用该选项。

在隔离 checkout 中：

1. 确认构建上下文只包含本仓库；
2. 将 bridge 配置设为 false，删除旧 upstream 变量；
3. 暂时重命名或不可访问三个源目录并停止其端口；
4. 执行前端安装/构建、后端依赖同步、迁移、单测和启动；
5. 调用 health、channels、provision-schema、keys 和 fake adapter，并确认
   `POST /admin/api/accounts/sync` 返回 404；
6. 扫描日志、产物和配置，确认没有源路径、旧端口和 Secret。

该验证是发布门槛，不是可选的手工检查。只要失败，状态就必须标为“仍依赖 bridge/源项目”。

## 9. 可复制的 PowerShell 门禁

以下步骤应在隔离 checkout 执行；删除或改名源目录前先确认其中没有本项目需要保存的文件。生产环境不要直接在运行中的共享目录执行。

```powershell
# 1) 使用仓库门禁，自动检查目标配置并在随机端口启动 API
python scripts/check-doc-links.py
python scripts/verify-clean-build.py

# 2) 确认源项目端口未被使用（按实际部署补充检查）
Get-NetTCPConnection -LocalPort 7863,7864,9090,8000 -ErrorAction SilentlyContinue

# 3) 在干净 checkout 中安装、检查、测试和构建
Set-Location web
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm build
Set-Location ..\services\api
uv sync --extra dev
uv run ruff check .
uv run pytest

# 4) 另开终端启动后检查健康、渠道、Key 和 fake adapter
uv run uvicorn app.main:app --host 127.0.0.1 --port 8080
```

执行完成后再扫描：

```powershell
rg -n "F:\\token-p|wb2api|doubao2api|chatgpt2api|:7863|:7864|:9090|:8000" `
  app tests Dockerfile pyproject.toml ..\..\web ..\..\.env.example ..\..\docker-compose.yml
```

扫描命中运行时代码、镜像或生产配置即阻断发布；只允许迁移矩阵、fixture 或明确隔离的兼容文档命中。
