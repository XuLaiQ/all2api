# 三渠道代码迁移矩阵

本文记录“从三个源项目迁移行为到 All2API 内置 adapter”的可追踪清单。它不是运行时集成清单。任何复制、重写或引用都必须补充版本、许可证、代码 hash、审查人和测试 fixture；账号数据、Cookie、OAuth token、浏览器 profile 和运行态数据库一律不迁入。

## 1. 迁移登记字段

每条迁移记录至少包含：

```text
source_project / source_revision / source_file_and_symbol
behavior_and_input / target_module / rewrite_or_copy
license_review / dependency_review / fixture
security_review / owner / status / evidence
```

状态只允许：`未审计`、`已审计`、`重写中`、`契约通过`、`已内置`、`拒绝迁移`。

## 5. 迁移实施规则

1. 先写行为 fixture，再写目标实现；fixture 脱敏且不含可用 token。
2. 先迁移纯算法/协议映射，再接入真实平台 client；禁止先把旧 HTTP endpoint 作为永久适配器。
3. 每个目标模块必须通过 adapter contract 和安全扫描后才能合并。
4. 源项目 license 不允许直接复制时，改为独立重写并只保留公开协议行为；仍需记录参考来源。
5. 迁移完成后运行时搜索必须找不到源项目 import、源路径和旧端口；bridge 代码要么删除，要么移动到明确的 `compat/legacy_bridge` 且默认不可构建生产镜像。
6. 账号迁移采取用户确认导入，不批量复制源项目的凭据目录；导入过程只接受显式 payload/secret manager 引用。
